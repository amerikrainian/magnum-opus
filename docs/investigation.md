# Opus Magnum accessibility mod: initial investigation (2026-11-03)

## 1. Game facts (verified)

- Install: `C:\Program Files (x86)\Steam\steamapps\common\Opus Magnum`, Steam appid 558990.
- `Lightning.exe` is one .NET Framework 4.x, x64, IL-only assembly (assembly name `Lightning`, version 1.0.0.0). Zachtronics' own SDL2 + D3D11 engine, the same generation as EXAPUNKS. References only mscorlib, System, System.Core, System.IO.Compression.FileSystem and Steamworks.NET 2025.163.
- No `Lightning.exe.config` ships, so the Echopunks injection (a config naming our AppDomainManager) is purely additive.
- Obfuscation: Eazfuscator.NET 3.3.149 to 3.4 (de4dot detects and cleans it). 1270 types, of which 168 keep real names (`GameLogic`, `Sim`, `Part`, `Molecule`, `Atom`, `SolutionEditorScreen`, `PuzzleSelectScreen`, ...). All member names are `#=q...`.
- Entry point `GClass57.Main` (de4dot name): `new GameLogic()`, `method_9()` (init), then `method_24()` (per-frame tick) forever.
- Init calls `SteamAPI.RestartAppIfNecessary`, so `steam_appid.txt` (558990) belongs in the game folder, exactly as in Echopunks.
- Screen stack: `GameLogic.class7_0`, a `Class7<IScreen>` wrapping a `List<IScreen>`. `method_5()` returns the top screen; `method_6()` returns the one below it.
- Real-named screens: ControlsScreen, CreditsScreen, DlcCreditsScreen, DocumentScreen, JournalScreen, JournalSubmissionScreen, MessageBoxScreen, OptionsScreen, PuzzleEditorScreen, PuzzleInfoScreen, PuzzleSelectScreen, SolitaireScreen, SolutionEditorScreen, SolutionRecorderScreen, UploadMessageScreen. A further 9 screens have obfuscated names (GClass9, 31, 36, 62, 86, 93, 98, 220, 225 in de4dot naming).
- Achievements: `SteamUserStats.SetAchievement`/`IndicateAchievementProgress` in CreditsScreen, DlcCreditsScreen, SolitaireScreen and GClass31 (research/journal counters).
- Boot click-gate: the game waits for a mouse click before the first tick, the same as EXAPUNKS. Echopunks' any-key fix (`SplashPatches`) should port over.

## 2. Injection proof (done live, then fully removed)

A minimal net48 x64 AppDomainManager with `Lightning.exe.config`, `0Harmony.dll` (2.4.2) and `steam_appid.txt`:

1. The CLR instantiated it in the default domain on CLR 4.0.30319.42000, 64-bit.
2. `Assembly.GetEntryAssembly()` is null at that point. Calling `Assembly.LoadFrom(<exe>)`, as Echopunks' Bootstrap does, CRASHES Opus Magnum: the CLR's own later load of `Lightning.exe` fails with FileLoadException 0x8000FFFF. The fix is to hook `AppDomain.AssemblyLoad` and act when `Lightning` loads (the SpeechChem pattern). This worked.
3. A Harmony prefix on `GameLogic` method ordinal 24 (token order) ran every frame once the click-gate was passed. It logged top-screen changes: an obfuscated intro screen, then `PuzzleSelectScreen`.

The game folder was restored to its original 12 files afterwards.

## 4. Community tooling (QuintessentialOM, cloned into `third_party/quintessential-*`)

- `om_mappings` has three layers:
  1. Obfuscated to intermediary: one JSON per build, keyed by MVID, generated by `matcher`.
  2. Intermediary names (`class_174`, `method_804`), stable across builds.
  3. Intermediary to human names: `named/mappings_ce_0.1.0.txt` plus `named_generated` and `auxiliary/render_mappings`.
- Human-name coverage of the CE 2026-10-22 build: 852/944 obfuscated classes, 1720/2124 methods, 3004/3706 fields. `documentation/Lightning.xml` has XML doc comments for some members.
- There is NO mapping for the installed public build (or any public build). The newest is CE 2026-10-22 (MVID `42f8deb3-...`). CE mappings appeared 0 to 1 days after each game update.
- `matcher` is a C# port of FabricMC Matcher. Inputs are hardcoded. It needs the PREVIOUS build's exe and mapping plus the new exe, and emits the new build's mapping. GPL-3.0.
- `OpusMutatum` (installer/patcher) runs these steps:
  1. Copy the CE game folder.
  2. "Coreify" `Lightning.exe` into `modded/Lightning.dll` for .NET 10. Coreified assemblies reference an `OpusMutatum` shim assembly.
  3. Remap to intermediary, then to human names (`NamedLightning.dll`).
  4. MonoMod-merge each mod's single declared DLL into `ModdedLightning.dll`.
  5. Run it with `dotnet modded/ModdedLightning.dll`.
  The default user task list ends `merge --asNamed`, so the modded game carries the HUMAN names. It does not connect to Steam and keeps separate saves (`Documents\My Games\Opus Magnum\Modded`).
- Quintessential v0.9.0 (2026-10-24) consists of three mods (Core, Data, UI) targeting net10.0. A mod is `modMeta.jsonc` plus one DLL plus Content; the mod class derives `QuintessentialMod` (`Load`, `LoadContent`, `PostLoad`, `Unload`, ...). `"mappings"` declares which name layer the DLL was compiled against, and OpusMutatum remaps it before merging. Patching is merge-time MonoMod (`patch_X` classes, `orig_` wrappers). The setup kit ships no runtime-detour library.
- Licenses: matcher is GPL-3.0. Quintessential, OpusMutatum, om_mappings and TemplateMod carry NO license file (all rights reserved by default). Ask before shipping anything derived from om_mappings, or generate our own.
- Mod list (wiki `General/Mod-List.md`): mostly content mods adding atoms, glyphs, campaigns and journals, many with CE ports, plus a few QoL mods. A reader that takes atom, part and puzzle names from game data and registries covers most of them without per-mod work.

## 5. Consequences for architecture

- Vanilla injection: the Echopunks model as-is (AppDomainManager config, net48 x64, Harmony 2.4.2), except Bootstrap must use the AssemblyLoad event (see 2.2).
- Modded injection: there is no AppDomainManager on CoreCLR. The clean route is a tiny Quintessential mod (net10.0 shim) whose `Load()` loads our real host and module from its own folder. Harmony 2.4.2 ships a net10.0 build (`third_party/harmony/net10.0/0Harmony.dll`).
- Hot reload: net48 means byte-loading into the AppDomain with no unload (Echopunks); net10 means a collectible AssemblyLoadContext (Guildrun).
- The Guildrun split fits: netstandard2.0 Contracts and Core shared by both runtimes, two thin hosts, and a Module multi-targeted net48 plus net10.0.
- Names: the module should compile against HUMAN names (a reference assembly built from obfuscated, intermediary and named layers, then publicized). The host remaps at load:
  - vanilla: named to intermediary to obfuscated, via the mapping for the running MVID;
  - modded: named(ours) to intermediary to named(theirs), read from `modded/Mappings`.
  This replaces Echopunks' de4dot `namemap.tsv`. An unknown MVID must fail loudly and audibly.

## 6. Decisions (2026-11-03)

- Target branch: **community-edition**. The user switched the install. The stock game uses our own loader (config file, Steam and achievements intact). The Quintessential copy is an opt-in second target via a shim mod.
- Name mappings: om_mappings may be used (user decision).

## 7. CE verification (2026-11-03, live)

- Steam manifest: `BetaKey community-edition`, build 26115258. `Lightning.exe` MVID is `42f8deb3-ffe7-44b7-b3ab-037e2df2b2e0`, exactly the mapping `mappings_ce_20261022_42f8deb3-...json`.
- Mapping completeness against this exe (Cecil check):
  - all 1,047 in-assembly classes, 4,147 fields and 4,599 methods it lists resolve with exact names and signatures, zero ambiguous;
  - its other 168 class entries are external references (System.*, Steamworks.*);
  - not in the mapping: SDL2.SDL and its 7 nested structs (real names, identity), 217 obfuscated enums with no members, and one 10-method native-interop helper class.
- The mapping JSON lists members in metadata (token) order, which held for all 959 comparable classes. So the stability table in the next section measures real metadata positions.
- Injection on CE: the same probe (AssemblyLoad hook, Harmony prefix on the tick) works. After the click-gate, Steam is live in-process: `SteamApps.GetCurrentBetaName` reports `community-edition`, `GetAppBuildId` reports 26115258, and all 7 achievements are readable (ALL_PUZZLES, ALL_PUZZLES_DLC, JOURNAL_24, RESEARCH_10, SOLITAIRE_1/2/3; none unlocked on this account). The CE decompile still calls `SetAchievement`/`IndicateAchievementProgress` at the same sites. Nothing was unlocked during testing.
- Reflection ordinals (`GetMethods(DeclaredOnly)`, token order) skip constructors; Cecil and the mapping include them. The CE tick is reflection ordinal 24 and Cecil/mapping index 26.
- Human names for the hook points: `GameLogic.instance` (field_2434), `GameInit` (method_942), `GameLoop` (method_957, the tick), `GetCurrentScreen` (method_938), `PushScreen` (method_945/946), `PopScreen`, `screenStack` (field_2454).

## 8. Stability across CE updates

Measured from consecutive om_mappings files (the share of carried members at the same metadata position within their class):

| Update | Methods | Fields |
|---|---|---|
| 07-04 to 07-09 | 100% | 100% |
| 07-09 to 07-29 | 100% | 99.7% |
| 07-29 to 10-15 | 99.6% | 99.9% |
| 10-15 to 10-22 | 100% | 100% |

Signatures were unchanged for all but 4 methods. Caveat: these numbers come from matcher output, so they're partly circular. Type (class) position stability has not been measured.

This supports a layered resolver at boot:
1. a bundled mapping;
2. a downloaded mapping for an unknown MVID;
3. self-resolution of only the members the module uses (same class, position and signature; ambiguous means unresolved);
4. verification on every path, with per-feature failure that is spoken.
